# 휴대폰 자체 디자인과 실시간 메시지 동작

2026-10-01 구현. Ren’Py 네이티브 화면이며 웹 화면을 사용하지 않는다.

## 화면과 등장

게임 중앙의 가상 스마트폰. 짙은 청록 프레임, 얇은 금속색 테두리, 원형 카메라, 크림색 화면과 청록색 보낸 메시지. Apple 로고 및 iMessage 명칭을 사용하지 않는다. 화면 좌측 홍보 문구는 제거했다. 시안은 디자인 방향이며 실제 화면의 배치와 버튼은 구현에 맞춰 조정했다.

휴대폰은 화면 아래에서 중앙으로 0.42초에 올라오고 닫을 때 내려간다. P키로 열고 일반 열람에서는 P 또는 Esc로 닫을 수 있다. 스토리 필수 휴대폰 화면은 답변 도착 후 계속 버튼으로 진행한다. 움직임 줄이기를 켜면 이동을 생략하고 입력 중 점도 정적으로 표시한다.

## 답장의 시간 흐름

| 답장 선택 후 | 상태 |
|---|---|
| 즉시 | 플레이어 메시지가 나타남 / 전송 중 |
| 약 0.6초 | 전송됨 |
| 약 1.2초 | 읽음 / 상대 이름과 입력 중 표시 |
| 약 3.8초 | 상대 답변 도착 / 입력 중 표시 사라짐 |

입력 중에는 세 점이 순서대로 밝아지고 위아래로 작게 움직인다. 시간은 실제 플레이 중 화면 타이머를 기준으로 하므로 시스템 시간 변경에 영향을 받지 않는다. 저장·불러오기·설정·대화 기록 화면에서는 전송 진행을 멈춘다. 현재 진행 중 메시지를 한 번에 하나의 대기 항목으로 관리한다. 시간은 고정값이며 후속 이벤트마다 typing_at/arrive_at를 조정할 수 있다.

다른 연락처로 이동하거나 휴대폰을 닫아도 답변은 예정된 시간에 한 번 도착한다. 다른 화면에서 도착한 메시지는 알림과 연락처의 미확인 개수로 표시한다. 해당 대화를 열면 미확인 개수를 해제한다. 같은 선택지를 다시 실행해도 답장과 호감도 보상이 중복되지 않는다. 읽음 표시는 시나리오 상태이며 실제 외부 채팅 서버와 연결하지 않는다.

## 저장과 기존 게임 규칙

대기 답변, 경과 시간, 전송 상태와 미확인 개수는 Ren’Py 저장 데이터에 포함된다. 입력 중 저장을 불러오면 해당 저장 시점의 대기와 메시지 목록을 복원한다. 기존 저장에 새 필드가 없으면 빈 대기 상태로 처리한다. 사진 수신 동의, 사진 저장/숨기기, 하루 답장 보상, 첫날 분기와 관계 수치는 유지한다.

## 현재 범위

현재 첫날 리아의 빠른 답장 이후 반응에 적용했다. 처음 도착해 있는 메시지는 기존 시나리오대로 즉시 보관된 상태이며 입력 중 연출로 재생하지 않는다. 통화는 기존 수신 선택과 대사 진행 방식이다. 자유 입력 채팅, 실제 음성 통화, 외부 문자 서비스는 구현 범위에 포함되지 않는다. 사진 기능에 새 캐릭터 사진을 생성하지 않았다.

## 코드와 검증

phone_live.rpy: 저장 가능한 대기 답변, 전송 상태, 입력 중 표시, 백그라운드 전달 타이머.
state.rpy: 즉시 붙이던 상대 답변을 대기로 전환하고 저장 복원 처리.
screens.rpy / ui_design.rpy: 중앙 스마트폰, 입출장, 연락처, 수신 설정과 메시지 UI.

기존 office_qa는 3개 사례 / 21개 조건 통과. office_phone_live는 18개 조건 통과. 전송 단계, 입력 중, 연락처 이동, 닫은 후 도착, 중복 방지와 대기 중 저장/복원을 검사한다. 결과 로그는 RenPy_게임/기록/검수로그/phone_live_output.txt 및 phone_qa_output.txt에 저장한다. 실제 실행 화면은 보관자료/01_예전시안/UI_실행_v4 폴더에 모은다. 변경 전 화면·상태·스타일 파일은 변경백업/휴대폰_날짜시간에 보관했다.
