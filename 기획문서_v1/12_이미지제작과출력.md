# 12. 성인 지향 이미지 제작과 출력

## 1. 이 문서의 범위

제공된 성인 캐릭터 마스터를 기준으로 비노골적인 오피스·패션·데이트·로맨스 이미지를 만드는 작업 가이드다. 사용자 요청의 성인 분위기를 성숙한 인물, 의상, 조명, 사적인 관계의 맥락으로 구현한다. 노골적인 성행위·성기 노출·성적 신체 부위 중심의 이미지 또는 그것을 생성하는 방법은 다루지 않는다.

특정 생성 서비스의 성인물 허용 여부, 최신 모델 기능·가격은 확인된 사실로 제시하지 않는다. 실제 도구를 정한 뒤 공식 정책·입출력 규격·상업 이용 조건을 확인해야 한다. 제한을 우회하기 위한 표현 변경은 제작 파이프라인에 넣지 않는다.

현재 네 원본은 일러스트다. 게임에서 같은 사람처럼 보이는 것이 우선이므로 애니메이션·일러스트 계열 그림체를 유지한다. 실사 전환은 원본 얼굴과의 동일성을 보장할 수 없는 별도 스타일 검토 작업으로 취급한다.

## 3. 향후 첫 제작 순서

아래는 향후 이미지 작업이 승인된 때의 절차다. 이번 MD 동기화에서는 생성·편집·복사·파일명 변경을 실행하지 않는다. 시작 전 03의 해당 MASTER와 04~07·11의 허용 범위를 확인한다.

1. 원본 4장을 읽기 전용 보관하고 작업용 복사본 생성.
2. 캐릭터별 정면 얼굴·전신·색·소품을 정리한 참조 시트 작성.
3. 원본의 실제 크기·색 공간·알파 유무 기록. 어두운 배경을 투명으로 착각하지 않기.
4. 기본 standing 4종의 배경 분리와 가장자리 수정.
5. 한 캐릭터의 표정2종으로 좌표·그림체 일치 여부 테스트.
6. 동일 캐릭터의 캐주얼 1종과 데이트 CG 1종 제작.
7. 게임 배경과 폰 화면에 넣어 가독성·크기 검수.
8. 얼굴 일관성과 출력 품질 통과 후 나머지 인물로 확대.

## 5. 프롬프트 설계식

`참조 이미지의 인물 유지 + 설정상 성인 나이 + 장면 목적 + 표정과 동작 + 의상 + 배경 + 조명 + 카메라·안전영역 + 그림체 + 출력 목적`

03에서 식별한 실제 승인 MASTER 이미지를 도구의 참조 입력으로 전달하고, 변경할 표정·자세·의상·구도만 지정한다. 실제 전달 여부를 작업 기록에 남긴다. 참조를 전달하지 않았다면 MASTER 참조 생성으로 기록하지 않는다. 참조 이미지를 입력할 수 있는 제작 흐름을 우선 가정한다. 실제 도구에 참조·편집 기능이 없으면 마스터 기반 수작업 편집 또는 원화 작업으로 전환한다. 나이 텍스트만으로 성숙한 외형이 보장되지 않으므로 결과를 눈으로 확인한다.

## 6. 비노골적 생성·편집 프롬프트 예시

공통 입력: 03의 해당 인물 승인 MASTER를 실제 이미지로 첨부한다. 공통 제약: MASTER의 얼굴·기본 비율·그림체와 개인 문서의 보존 앵커를 유지하고 각 예시에서 명시한 변경만 요청한다. A는 기본 오피스 정리, B~E는 허용된 장면·의상·표정·구도 변형이다. 아바타는 새 얼굴 생성 대신 승인된 얼굴 자산을 크롭한다. 이 예시는 향후 작업 지침이며, 17의 과거 실제 사용 프롬프트를 교체하지 않는다.

### A. 서윤의 기본 스탠딩 정리

참조 이미지와 동일한 성인 여성 캐릭터 한서윤, 설정상 만 34세. 갈색 낮은 번 헤어와 얼굴 주변 잔머리, 차분한 갈색 계열 눈, 작은 둥근 귀걸이와 손목시계를 유지한다. 푸른 셔츠, 회갈색 긴 겉옷, 흰 바지와 검은 구두를 유지한다. 태블릿을 들고 편안하게 서 있는 전신 오피스 일러스트. 얼굴과 신체 비율을 원본과 일치시키고 손가락과 태블릿 형태를 정확히 정리한다. 부드러운 선화와 원본의 채색 스타일. 머리·발끝이 잘리지 않는 구도. 배경은 투명 처리 요청이 가능한 출력이라면 투명, 아니면 분리하기 쉬운 단색으로 생성 후 후처리. 텍스트와 워터마크 없음.

### B. 리아의 카페 일상 사진

참조의 강리아와 동일한 얼굴과 금발 높은 포니테일, 푸른 계열 눈을 유지한 설정상 만 27세 성인 캐릭터. 네이비색 단정한 상의와 청회색 스커트. 카페 창가에서 커피를 들고 동료에게 인사하는 편안한 모습. 상반신 중심, 자연스러운 눈높이, 따뜻한 오후 빛. 원본과 같은 일러스트 스타일. 채팅 사진에 쓸 수 있도록 얼굴과 컵이 중앙 안전영역에 들어오게 구성. 글자 없음.

참조와 동일한 설정상 만 36세 백지현. 검은 턱선 단발, 얼굴 형태, 시계 유지. 단색 니트와 슬랙스의 단정한 퇴근 후 의상. 강변 야경에서 성인 동료와 나란히 걷고 서로의 얼굴을 바라보는 편안한 장면. 눈높이 구도, 도심 불빛은 부드럽게 흐리고 얼굴은 알아볼 수 있게. 원본의 성숙한 일러스트 스타일. 16:9, 하단 대사 안전영역 확보. 글자 없음.

## 7. 공통 수정 지시

얼굴이 원본과 다르면 얼굴만 교정한다. 손이 잘못되면 손과 소품 영역만 교정한다. 배경이 변해도 인물 조명 방향은 맞춘다. 배경 제거 시 검은 잔상·머리카락 주변 회색 테두리를 실제 게임 배경 두 종류 위에서 확인한다.

개별 수정 요청 예: “얼굴과 의상은 유지하고 오른손의 손가락과 컵을 자연스럽게 수정”, “포니테일 위치와 눈 색을 참조와 맞추고 다른 요소 유지”. 단순히 '더 성숙하게'만 반복하지 않고 얼굴 비율·표정·자세의 차이를 구체적으로 기록한다.

## 8. 실사 스타일을 별도로 원할 경우

애니메이션 마스터의 실사 변환은 게임용 기본 자산과 분리해 테스트한다. 실존 인물의 얼굴을 무단으로 결합하지 않고 허구의 성인 인물로 제작한다. 의상·헤어·분위기를 유지하되 결과를 원본과 동일 인물이라고 보장하지 않는다. 실사와 일러스트를 한 루트에 혼용하면 몰입이 깨질 수 있으므로 채택 전 스타일 결정을 한다.

실사 테스트용 장면은 단정한 성인 오피스 인물의 패션·프로필 촬영으로 제한한다. 촬영 언어는 부드러운 키라이트, 눈높이, 자연스러운 피부 질감, 단정한 의상, 업무 소품이다.

## 9. 출력 규격 — 프로젝트 목표

| 자산 | 작업용 목표 | 게임용 | 알파·색 |
|---|---|---|---|
| 전신 standing | 세로 2500px 이상을 목표, 원본 품질 우선 | 최대 1200×2000 안에서 비율 유지 | PNG, straight alpha, sRGB |
| CG·배경 | 3840×2160을 목표 | 1920×1080 | PNG 또는 고품질 WebP, sRGB |
| 폰 사진 | 1200×1600 또는 1600×1200 | 같은 비율의 경량 이미지·썸네일 | JPEG/WebP, sRGB |
| 프로필 | 512×512 | 256×256 | PNG/WebP |
| 표정 레이어 | 몸 레이어와 같은 캔버스 | 같은 좌표·크기 | PNG alpha |

위 표는 제작 목표이며 현재 파일의 실제 규격이 아니다. 실제 MASTER는 03·27에 기록한 1024×1536 RGBA PNG다. 투명 픽셀은 확인했으나 색 프로필·알파 해석·게임 배경 합성 적합성은 미확인 항목을 남겨 둔다. 리아 예시 시트 2048×768, 카페 CG 1672×941도 목표 규격으로 확대된 최종 납품본이라고 쓰지 않는다.

규격은 도구의 실제 출력 능력을 보장하지 않는다. 작은 원본을 무조건 확대하지 않는다. WebP 사용 여부는 선택 엔진의 읽기 지원을 확인하고 PNG 대체본을 보관한다. 투명 자산은 JPEG로 출력하지 않는다.

원화 파일은 별도 보관하고 게임용 파일만 압축한다. ICC 색 프로필과 알파를 일관되게 내보낸다. 검은 배경을 지운 뒤 alpha 경계가 premultiplied 상태로 잘못 해석되지 않는지 확인한다.

## 10. 게임에서 어떻게 보여 줄지

일반 대화: 장소 배경 + 투명 standing + 표정 + 대사창. CG: standing을 숨기고 전체 화면 CG로 전환. 친밀 장면: 서로 가까워지는 대사와 CG 뒤 암전·다음날 배경으로 이동. CG 갤러리: 본 장면만 해금하고 재생은 수치를 변경하지 않는다.

폰 사진: 대화방의 작은 썸네일을 누르면 폰 내부 이미지 뷰어. '크게 보기'를 누르면 게임 내 전체 화면 뷰어. 이미지에 채팅 문구를 생성하지 않고 UI에서 텍스트를 올린다. 사진 닫기 후 같은 대화 위치로 돌아간다. 실제 OS 사진 앱이나 외부 네트워크는 열지 않는다.

향후 파생 파일명은 ASCII로 통일하고 표시 이름만 한국어로 사용한다. 이미 승인된 한국어·공백 포함 원본은 이름을 변경하지 않는다. 향후 수정 버전은 증가시키되, 파일명이나 높은 버전 번호를 승인 근거로 삼지 않는다.

자산 승인 manifest는 현재 프로젝트 자료에서 발견되지 않았다. 새 manifest나 형식·구현 시스템을 이번에 만들지 않는다. 현 승인 대응은 03에 수동 기록하고 향후 manifest 연결이 필요하다. `assets.rpy`는 표시용 레지스트리이며 승인 manifest가 아니다. 정식 납품 대본은 승인 자산을 참조해야 한다. 현재 시제품의 리아 예시 시트·카페 CG 사용은 명시된 임시 예외이고 최종 원화 미승인 상태를 유지한다.

## 12. 납품 확인

동일 인물·성인 외형·헤어·의상·손·소품·원근·광원·알파·안전영역·대사 가독성·메모리·전화 화면 크롭을 확인한다. 사용권과 도구 이용조건 확인은 제작자 기록에 남긴다. 생성 실패를 대본의 설정 변경으로 덮지 말고 원본 기준으로 수정한다.
